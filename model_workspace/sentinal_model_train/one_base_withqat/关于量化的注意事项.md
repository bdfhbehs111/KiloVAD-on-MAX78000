E6 执行时照着做这几条，缺一条就可能又出一个“恒报人声”的坏模型：

1. **量化一律带 `--clip-method SCALE`**
   ```powershell
   python quantize.py <in.pth.tar> <out.pth.tar> --device MAX78000 --clip-method SCALE
   ```
   裸跑（不给 `--clip-method`）会沿用 QAT 的 per-layer shift，而那个 shift 是按**权重幅度**推导的，不看激活分布 → 整型前向退化成偏置常数。
   > 前提：`izer/quantize.py` 已在 `params_r = ...` 后补了 `distribution_factor = None`，否则给 `--clip-method` 直接 `UnboundLocalError`。换机器/重装 SDK 后先确认这一行还在。

2. **E6 的 AUC 指标必须测量化后的模型，不是 QAT 的**
   QAT 里 `adjust_output_shift = 0`，shift 从未被训练过，QAT 报的 97.x% 是浮点激活上的数字。把“AUC 掉 <0.002”改成：**`--clip-method SCALE` 量化后的模型 vs 浮点模型，在同一批测试样本上的 AUC 之差 < 0.002**。

3. **量化后立刻跑三条判别力验收**（用 `ai8xize --sample-input`，4 秒一个点）：
   - 全零输入 与 真实人声样本 的 `s0−s1` **必须不同**
   - 同一类的不同样本，`s0−s1` **不能全一样**
   - 上面两条过了才看 accuracy
   第 1 条单独就能挡住我们踩的那个坑（当时全零和真实人声都给 +13）。

4. **增益 k 在量化修好之后再标定，别提前扫**
   修好前扫任何 k 都是常数，白白浪费几轮。修好后用同一套 `--sample-input` 扫 `k ∈ {4,8,16,32}`，取“人声全为负、非人声多数为正”的拐点（E2.5 的基线模型是 16，剪枝后要重扫）。

5. **别用 `ai8x.simulate` 当硬件模型**
   它是 QAT 口径（simulate 模式跳过 `out_shift -= activation_threshold`），`conv2.output_shift=0` 会让 64×int8×127/128 ≈ 5000 直接 clamp 到 127，输出恒等。只信 `ai8xize --sample-input` 出的 `sampleoutput.h`。
   传进去的 npy 必须是 **int64**，形状 `(128,128)`。

6. **类别方向**：`datasets/sentinel.py` 的 `output: ('nonvoice','voice')` → `s0`=类0=非人声。
   **`voice ⟺ s0 − s1 < 0`**。写成 `> 0` 会得到一个“永远说人声”或“永远说非人声”的模型，而且看起来还像在工作。

7. **每换一次 `-q` checkpoint 都要重新 ai8xize + 重跑 `make_plug.py`**，别手工改 `plug/` 产物。`make_plug.py` 里已注入两处必须的修补：`NVIC_SetPriority(CNN_IRQn, 5)` 和 `sen1_cnn_time` 定义 —— 少任一条，上板第一次推理就死在 FreeRTOS 断言里，串口一个字节都不出。

8. **烧录前确认 hex 是新的**：`make` 的默认目标只跑 `size`，不生成 hex。要么 `make` 后手动 `objcopy -O ihex`，要么直接 `make flash`。
