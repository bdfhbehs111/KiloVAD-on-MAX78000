# one_base_prune —— E4 剪枝搜索（目标模型 = 逐带归一化后的 one_base）

从 `zero_base_last/` 复用而来。**判据、切片、评估、CSV 结构、Optuna 目标函数一行没改**，
只改了「目标模型」和「评估口径」两件事。

| | zero_base_last | 本目录 |
|---|---|---|
| 基线 ckpt | `zero_base___2026.10.31-170625/zero_base_best.pth.tar` | `one_base___2026.11.03-182532/one_base_best.pth.tar`（ep27） |
| 输入预处理 | 原样 int8 折叠波形 | **逐带归一化** `normalize_per_band`（E2） |
| 搜索脚本文件名 | `optuna.py` | `optuna_search.py` |
| 评估口径 | 只有 test | **val + test 都落盘**，排序只看 val |
| 基线参照值 | 写死 `0.011809 / 0.996197` | 由 `--expect-fpr / --expect-auc` 传入 |

## 三个文件

| 文件 | 阶段 | 作用 | 需要 optuna? |
|---|---|---|---|
| `prunning.py` | E4a | 逐层单层敏感度扫描（18 点），产 `results.csv` / `results.txt` / `ckpts/` | 否 |
| `optuna_search.py` | E4b | 多目标（Pareto）组合搜索，产 `study.db` / `pareto.json` | 是 |
| `_verify.py` | E4c | 前沿候选多 seed 复核，把「seed 噪声」和「真差异」分开 | 否 |

`optuna_search.py` 与 `_verify.py` 都通过文件路径加载 `prunning.py`，**判据只有一份**。
改 `channel_importance` / `evaluate` / 切片，两个下游立刻跟着变。

## 跑法（全部在本目录下）

```powershell
$py = "C:\Users\13157\miniconda3\envs\ai8x\python.exe"

# 0) 门禁
& $py prunning.py --smoke --device cuda

# 1) E4a：逐层敏感度（18 点 + baseline）。边跑边落盘，崩了 --resume 接着跑
& $py prunning.py --device cuda --out prune_e4a

# 2) 按 steps 1 的表重填 optuna_search.py 里的 SPACE / SEED_TRIALS，然后验链路
& $py optuna_search.py --selftest --expect-fpr <baseline 的 fpr_at> --expect-auc <baseline 的 auc>
& $py optuna_search.py --smoke

# 3) E4b：正式搜（--device 默认 cpu，必须显式给 cuda）
& $py optuna_search.py --n-trials 40 --ft-epochs 5 --lr 1e-3 --device cuda --out prune_e4b
#    补训练预算：给前沿前 6 名换 3e-4 / 12ep 重跑
& $py optuna_search.py --n-trials 0 --polish-epochs 12 --lr 3e-4 --device cuda --out prune_e4b

# 4) E4c：复核
& $py _verify.py --top 6 --seeds 3 --device cuda
```

`--ckpt <任意 .pth.tar>` 三个脚本都支持，换基线不用改代码。

## E4a 实测（已跑完，18/18，1h46m）

baseline: `W 79,392 B  cycles 118,272  val AUC 0.996105 / FPR 0.012627  test AUC 0.995824 / FPR 0.010952`

| 现象 | 数字 |
|---|---|
| **FPR@TPR95 不可排序** | 18 个点的 dFPR 在 val/test 上符号一致只有 **8/18**，spearman **0.008** |
| val 与 test 的系统差 | FPR `mean +0.0043 / sd 0.0029`；AUC `mean −0.00031 / sd 0.00065` |
| 唯一可靠的信号 | conv1 16ch：val AUC −0.0018、FPR ×2.2；test AUC −0.0010、FPR ×1.8（唯一双向同向恶化） |
| 唯一被推翻的先验 | zero_base 说 conv3 最划算；one_base 上 conv3 72ch 反而 −0.0018 AUC（非单调 = 坏 seed） |
| cycle 结构 | conv2 42% + conv3 31%，两者 `ceil(96/64)=2`，两个最大台阶都在「≤64」这个阈值上 |
| cycle 地板 | conv1 恒 16,384，但 conv2 的 cycle = c1·3·128 → **conv1 是 cycle 的最大杠杆** |

所以 `optuna_search.py` 的 `SPACE` 已按上表重填，**只改了 conv1 下界 16 → 32**，其余沿用
zero_base（它们在 one_base 上没被推翻，保持不动才能与 zero_base 的 E1c 并排看）。

## 为什么 zero_base 的结论不能直接搬

E2 改的是**输入分布**（逐带归一化），不是权重。归一化把幅度侧信道压掉之后：

- 模型不再靠响度走捷径 → 学到的特征分布变了，**逐层冗余结构跟着变**
- 实测确认：zero_base 的「conv3 最划算」在 one_base 上**反转**了（conv3 砍 25% 反而
  −0.0018 AUC）；zero_base 的「conv1 到 16ch 才开始疼」也不成立（16ch 双向恶化）
- 所以 `zero_base_last/E1C_RESULT.md` 的 Pareto 前沿和噪声地板（±0.003）只作参考
